# Snack 프로젝트 정리 (Snack용)

아래 내용은 프로젝트 소개/회고 문서, 포트폴리오 “Snack” 섹션 등에 **그대로 붙여넣기** 좋게 정리한 버전입니다.

---

## 1) 기술 스택

### FE

- **프레임워크 & 언어**: Next.js, React, TypeScript  
- **UI & 스타일링**: Tailwind CSS, tailwind-merge  
- **상태 & 데이터 관리**: React Query, Zustand, Zod, React Hook Form  
- **개발 도구**: ESLint, Prettier, Sentry  
- **유틸리티/외부 연동**: clsx, OpenAI, TossPayments SDK  
- **배포 & 협업**: Vercel, GitHub, Figma, Notion

### BE

- **프레임워크 & 언어**: Node.js, Express.js, TypeScript  
- **테스트 & 품질**: Jest, Sentry, Swagger  
- **DB**: Prisma, PostgreSQL  
- **인프라 & 유틸리티**: Axios, CloudFront, S3, node-cron, Docker  
- **배포 & 협업**: Route53, RDS, EC2, GitHub, Notion

## 2) 주요 구현 기능

## 2-1. Product API (백엔드)

### 구현 목표

- 상품 등록/목록·상세/수정/삭제 및 내 상품 관리 제공  
- Swagger 문서화로 협업 효율 확보  
- 대용량 목록을 위한 **커서 페이지네이션·정렬·카테고리 트리 필터**와 안정적인 **이미지 업로드 파이프라인** 구축

### 주요 구현 내용

- **라우팅 & 계층 분리**: Express 기반 Controller / Service / Repository 구조  
- **주요 API**
  - `POST /product`: 상품 등록  
  - `GET /products`: 목록 조회(정렬·카테고리·커서 페이지네이션, `nextCursor`)  
  - `GET /products/{id}`: 상세 조회  
  - `PATCH /products/{id}`: 상품 수정(작성자/관리자)  
  - `DELETE /products/{id}`: 상품 삭제(소프트 딜리트)  
  - `GET /product/category`: 카테고리 트리  
  - `GET /my/products`: 내 상품 목록(메타 포함)
- **이미지 업로드**: Multer → `uploadImageToS3` → `getCloudFrontUrl`로 최종 URL 반환(예: `src/utils/s3.ts`)  
- **조회 고도화**: 정렬, 카테고리 부모 선택 시 하위 포함, 커서 기반 페이지네이션  
- **찜 연동**: 조건부 include로 `isFavorite`를 서버에서 합성 반환(FE 추가 쿼리 불필요)  
- **삭제 트랜잭션**: 상품 소프트 딜리트 + 관련 CartItem 소프트 딜리트 + Favorite 정리(원자적 처리)  
- **DTO/타입 명확화**: `product.dto.ts`, `product.types.ts`로 입력/응답/쿼리 옵션 정의

### 기술적 성과

- 커서 페이지네이션·카테고리 트리·인기 정렬로 **대용량 목록 응답 성능 향상** 및 FE 구현 단순화(`isFavorite` 서버 합성)  
- S3+CloudFront 업로드 파이프라인(안전 파일명·에러 매핑)으로 안정적 이미지 제공  
- 소프트 딜리트 + 연쇄 정리 트랜잭션으로 데이터 일관성 보장

## 2-2. 회원 관리 페이지 (프론트엔드)

### 구현 목표

- 회사 구성원 목록을 한 화면에서 **검색/페이징/초대/삭제/권한 변경**까지 직관적으로 제공  
- 모바일/태블릿/데스크톱 반응형 UI와 접근성(ARIA) 준수

### 주요 구현 내용

- **컴포넌트 구조**
  - `User`: 목록 조회·검색·페이징, 초대/삭제 액션, 모달/토스트 관리 컨테이너  
  - `InviteMemberModal`: 회원 초대(이름·이메일·권한) + 권한 수정 모드 통합(검증/제출)  
  - `MemberList`: 구성원 행(모바일/데스크톱 레이아웃), 권한 변경/계정 삭제 트리거
- **권한 기반 제어**
  - 권한 변경/삭제/초대는 관리 권한 시나리오에 맞춰 모달로 수행  
  - 권한 수정 모드: 이름/이메일 읽기 전용, 권한만 변경
- **상태 관리**
  - 변경 작업 후 목록 재요청으로 최신성 보장
- **검증/피드백**
  - 초대 시 이름 공백·이메일 형식(Zod) 검증  
  - 이미 초대됨/이미 등록됨 등 충돌 상황은 구체 메시지로 안내
- **반응형/접근성**
  - 모바일: 카드형 + 메뉴 드롭다운 / 데스크톱: 테이블형(열: 이름/메일/권한/비고)  
  - 목록/테이블/내비게이션에 ARIA 역할·라벨 적용

### 기술적 성과

- 변경 후 목록 자동 갱신 + 즉시 토스트 피드백으로 데이터 최신성/사용자 신뢰 확보  
- 초대/권한수정/삭제 플로우를 모듈형 컴포넌트로 분리해 재사용성·유지보수성 향상  
- 반응형 + ARIA 적용으로 실사용 환경 전반에서 접근성·가독성 강화

## 2-3. 주문 관리 페이지 (프론트엔드)

### 구현 목표

- 보류(대기) 주문을 한 화면에서 조회·정렬·페이징하고, 승인/반려 처리 및 예산 확인까지 즉시 수행  
- 모바일/태블릿/데스크톱 반응형 UI와 접근성(ARIA) 준수

### 주요 구현 내용

- **컴포넌트 구조**
  - `Order`: 대기 주문 목록 조회·정렬·페이징, 승인/반려 모달, 결제 진입, 토스트/로딩/쿼리 갱신  
  - `RequestList`: 주문 요약 행 목록(모바일/데스크톱), 승인/반려 트리거, 상세 페이지 이동  
  - `OrderManageModal`: 승인/반려 입력(관리자 메시지) + 예산 검증 + 상태 업데이트  
  - 타입: `TOrderSummary`, `TOrder` 등 리스트/모달용 타입 분리(예산/상품 세부 포함)
- **동작 흐름**
  - 회사별 대기 주문 조회 → 정렬(최신/가격↑↓) 및 페이지 전환  
  - 승인/반려 클릭 시 상세 주문 조회 후 모달에서 처리  
  - 승인 시 총액·배송비 반영 → 예산 차감 금액 계산 → 부족하면 차단, 충분하면 결제 플로우 이동  
  - 승인/반려 완료 또는 사용자 정보 변경 시 주문/예산 목록 재조회
- **상태/UX**
  - 화면 크기에 따른 가시 항목 수 변화에 맞춘 페이지 번호 자동 조정  
  - 스피너/토스트/상세 이동 제공  
  - 목록/테이블/버튼 ARIA 역할·라벨, 키보드 인터랙션 처리

### 기술적 성과

- 승인 플로우에 예산 검증을 통합하여 비즈니스 제약을 UI 레벨에서 선제 보장  
- 모듈형 구성(목록/모달/타입)으로 재사용성과 유지보수성 증대, 반응형·접근성 기준 충족  
- 상태 변경 후 자동 갱신으로 데이터 최신성 확보

## 2-4. 프로필 페이지 (프론트엔드)

### 구현 목표

- 사용자 정보 확인 및 프로필 변경(회사명/비밀번호)을 직관적으로 제공  
- 권한에 따라 편집 가능 항목을 구분하고, 반응형·접근성(ARIA)을 준수

### 주요 구현 내용

- **컴포넌트 구조**
  - `ProfileForm`: 폼 상태/검증/제출 orchestration, 토스트, 리다이렉트(`/products`)  
  - `ProfileField`: 라벨·값 표시/입력 재사용(회사명 표시/입력 모드)  
  - `ProfilePasswordSection`: 비밀번호/확인 + 보기 토글  
  - `ProfileSubmitButton`: 유효성/변경 여부/로딩 상태 기반 버튼 제어
- **권한 기반 제어**
  - 최고관리자만 회사명 편집 가능, 그 외 필드는 표시 전용  
  - 역할 라벨(일반/관리자/최고관리자) 표기
- **검증/입력 가드**
  - Zod 기반 폼 검증(react-hook-form 연동)  
  - 회사명 입력: 허용 문자 제한 + 최대 20자 트림, 에러 메시지/ARIA 연결  
  - “실제 변경”이 있을 때만 제출 가능(회사명 변경 또는 비밀번호 입력)
- **제출 플로우**
  - 변경사항에 따라 API 분기(회사명만 / 회사명+비밀번호 / 비밀번호만)  
  - 성공 시 폼 초기화 → 사용자 데이터 재조회 → 토스트 → 페이지 이동

### 기술적 성과

- 권한 인지형 폼 설계로 안전한 편집 경험 제공(편집 가능 항목 자동 제한)  
- 입력 가드 + 명확한 에러/토스트 피드백으로 UX 안정성 강화  
- 폼/필드/비밀번호/버튼 모듈화로 재사용성과 유지보수성 향상
